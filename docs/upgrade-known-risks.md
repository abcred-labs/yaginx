# 升级器独立风险

这些问题与自动升级调度的移除独立，应分别跟踪，避免扩大本次变更范围。

## dpkg 安装失败后的恢复

当前 runner 在 `dpkg -i` 返回失败时直接返回安装错误；并非所有安装失败都会进入
后续 readiness 失败回滚路径。失败可能留下未完成的 Debian 包状态，需要管理员
检查 dpkg 状态、日志和可信回滚包。本次不调整该恢复策略。

## 数据库迁移不可由包回滚撤销

`--migrate-database` 由管理员显式选择。迁移失败后的包恢复不能保证数据库结构
已恢复，必须检查迁移跟踪与备份；不要直接以包版本判断数据库兼容性。

## 本次验收中已修复的手动参数缺陷

- `--package-only` 过去会在错误记录器读取空配置时 panic。现在空配置直接禁用
  数据库错误记录器；CLI 仍不读取配置或连接 PostgreSQL。已补充入口回归及真实包内
  CLI 验证。
- `--skip-preflight-health` 过去会用空的预期 node ID 拒绝正常的新服务。
  现在仅在旧 node ID 已知时要求相等；新服务仍须返回有效非空 node ID、目标版本和
  ready 状态。已补充健康目标成功、不健康目标回滚及已知 node ID 不匹配失败测试。

这两处原有问题经管理员确认纳入本次手动参数验收；其他恢复策略仍保持独立范围。
